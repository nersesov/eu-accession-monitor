## 2. Lighthouse CI

Lighthouse 13.6.0, мобільна емуляція з імітацією повільної мережі й процесора (типові налаштування Lighthouse), по 3 прогони. Конфігурація: `lighthouserc.json`.

| Сторінка | Performance | Accessibility | Best Practices | SEO | LCP | CLS | TBT |
|---|---|---|---|---|---|---|---|
| `/` | 99–100 | 100 | 100 | 100 | 1,05–1,06 с | 0 | 74–98 мс |
| `/glava-23/sudova-reforma` | 100 | 100 | 100 | 100 | 1,05–1,06 с | 0 | 48–66 мс |

**INP** — польова метрика, у лабораторному прогоні її немає. Лабораторний замінник — TBT: 48–98 мс при порозі 200 мс. Реальний INP треба виміряти на розгорнутому сайті (Chrome DevTools → Performance, або дані реальних користувачів).

Пороги в CI: LCP > 2,5 с або CLS > 0,1 — помилка (деплой блокується); Accessibility < 95, SEO < 90 — помилка; Performance < 90, TBT > 200 мс — попередження.

## 5. Рішення, що впливають на швидкість

- Server Components: кільце та смуги прогресу — серверний SVG/HTML, без JavaScript на клієнті.
- Recharts завантажується окремим чанком після першого рендеру; місце під діаграму зарезервоване (без зсуву макета).
- Дані сторінок кешуються на 60 с і скидаються одразу після зміни в адмінці чи імпорту.
- Шрифт Inter розміщено локально (next/font): без запитів до сторонніх серверів, з `font-display: swap` і підігнаним запасним шрифтом.
- Анімуються лише `transform` та `opacity` (і одноразове заповнення кільця).
- На сервері Caddy стискає відповіді (zstd, gzip).
